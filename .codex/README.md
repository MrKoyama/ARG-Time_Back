# TIME BACK カスタムサブエージェント

設定・確認日：2026-10-23。対象：ARG-Time_Backプロジェクト。

この作業では設定を追加しただけです。サイト、AGENTS.md、docs、planning、物語は変更していません。エージェントの実起動・ARG制作・初見探索も実施していません。

## ファイルと責任範囲

| エージェント | 定義 | 責任・編集権限 |
|---|---|---|
| story_designer | [story_designer.toml](agents/story_designer.toml) | 既存設定と進捗を調査し、展開・謎・伏線・ページ案を提案。通常は応答のみ。保存する場合も許可された案の保存先だけ |
| web_developer | [web_developer.toml](agents/web_developer.toml) | ユーザー承認済みの設計を、割り当てられたファイル内で実装・検証 |
| continuity_reviewer | [continuity_reviewer.toml](agents/continuity_reviewer.toml) | 設定・時系列・画像・表現・伏線・導線を照合。ファイル変更なし |
| arg_player | [arg_player.toml](agents/arg_player.toml) | 独立環境で画面からだけ探索・記録・評価。環境不備やネタバレ混入時は停止。ファイル変更なし |

最初の3担当は、AGENTS.mdとdocsを参照する指示になっています。arg_playerには、その指示や作品の真相・検索正解・想定ルートを入れていません。

## 採用した公式仕様

現在の公式[Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)に従い、プロジェクトの.codex/agents直下に1担当1TOMLを置きました。必須のname、description、developer_instructionsを設定しています。

モデル関連フィールドは省略しました。「inherit」というモデル名や空文字を設定しているわけではありません。[設定リファレンス](https://learn.chatgpt.com/docs/config-file/config-reference)の優先順位に従い、呼び出し時指定・agentsの共通既定値があればそれが入り、なければ親の値へ継承します。確認時のユーザー設定には共通モデル・推論強度の既定指定はありませんでした。今後これらが変更されると継承元も変わります。

sandbox_mode、approval_policy、model_provider、mcp_serversを各定義に書いて隔離できるとは扱っていません。実際の権限・プロバイダ・MCPは親側の設定に依存します。レビュー担当の「変更しない」は行動上の指示であり、OSの読み取り専用制限ではありません。

arg_playerでは、公式に認められた機能制限のうちshell_tool、memories、request_permissions_toolをfalseにし、自動スキル指示と組み込みスキルを無効にしました。それでも履歴、AGENTS.md、すべてのツールやネットワークを隔離できるわけではありません。

既存の同名定義・プロジェクト.codexは見つからなかったため、上書きはありません。現行の自動発見方式を使うので、旧方式の[agents.<name>]登録や新しい.codex/config.tomlは追加していません。個人用設定も変更していません。

## 親担当から渡す作業契約

story_designer、web_developer、continuity_reviewerには、毎回次を渡します。

- 作業目的と対象ページ・範囲
- 参照文書と、ユーザーが実際に承認した内容
- 提案と未確定事項、変えてはいけない設定・開示段階
- 編集を許可するファイルと変更禁止ファイル
- 成果物、確認条件、他担当との共有ファイルの所有者

重要な物語変更の承認者はユーザーです。設計案を親担当が受領しただけでは承認済みになりません。

共有CSS、検索DB、番号・アーカイブの辞書は統合担当を一人に決め、複数担当が同時に変更しない運用です。各担当は根拠・状態区分・変更ファイル・検証・残課題を親担当へ返します。親担当が統合判断を行い、報告や解答をarg_playerへ横流ししません。

## 初見テスト用の独立環境（今回は未構築）

通常のサブエージェント定義だけでは初見性を保証できません。この制作リポジトリには真相を含むAGENTS.mdがあり、このチャットにも制作者情報があります。ここでarg_playerを起動しても正式な初見評価にはできません。

別途、次の条件を満たすテスト環境を構築する必要があります。

1. 会話の分岐・要約の継承ではない、新しい独立セッションを使用する。作者側の会話・メモリ・他担当の結果を渡さない。
2. 制作フォルダとその子孫を使わず、親ディレクトリにも作者用AGENTS.mdがない中立の作業場所にする。worktreeを作るだけでは足りない。
3. このarg_player.tomlだけを必要に応じて中立環境に配置する。制作側のAGENTS.md、docs、設定、検索登録一覧、他3担当の指示を持ち込まない。
4. プレイヤーに公開する版を固定し、ブラウザで閲覧できるよう管理者が配信する。制作リポジトリそのものはマウントせず、作者資料・旧素材が意図せず配信されないことを管理者が確認する。
5. 親側で、ブラウザの通常画面操作だけを使えるツール構成にする。シェル、ファイル読取、汎用Web検索、コネクタ、通信解析、任意スクリプト実行の経路を与えない。設定内の禁止文だけに頼らない。
6. ブラウザは新規プロファイル等で履歴・localStorage・訪問済みアーカイブを空にする。既存制作ブラウザを流用しない。
7. テスト版のURL範囲を環境側で制限し、外部サービスへ出られないようにする。配信側ではGAなどの外部通信もテスト用途に合わせて制限する。制作側の元ファイルは変更せず、実送信も発生させない。
8. 物語情報として渡すのはスタートURLのみ。時間・操作上限、画面幅、許可された操作といった中立な運用条件以外は渡さない。
9. テスト中はヒントや答え合わせを返さず、終了後に親担当が操作ログと評価を受け取る。汚染が判明したら結果を初見成功扱いしない。

この環境の構築・配信・テスト実施は今回の作業範囲外です。ブラウザツールがない場合にHTML読取へ切り替えて代用しない設定です。

- 使用したトップレベル項目・機能制限・skillsの項目を公式仕様と照合。
- モデル・推論強度の固定、無効なsandbox/権限上書き等がないことを確認。
- 既存ファイルとの衝突なし。プロジェクト内の元142ファイルを開始時ハッシュと照合して保全を確認する。
- この確認はTOML解析と公式仕様への照合であり、Codexが4役を実際に起動したことの証明ではない。

## Codexによる認識・起動確認の現状

ローカル実行ファイルはcodex-cli 0.163.0-alpha.11.2でした。モデルを呼ばずに入力を組み立てる「codex debug prompt-input」をプロジェクト直下から試しました。

- --strict-configを付けた診断は、このサブコマンドでは非対応というエラー。
- 通常の制限下ではCodex作業領域へのアクセス拒否で失敗。
- 承認された制限外の診断は終了コード0・JSON出力あり。ただしこの出力に4役の登録一覧は含まれず、カスタム役の発見・読込の確認には使えなかった。
- 現在のチャットに公開されているサブエージェント起動ツールにも、カスタム役を指定して非実行検証する項目はない。

したがって、**公式形式・構文は確認済み、デスクトップの現在のセッションによる4役の認識と実起動は未確認**です。診断が成功しただけで認識済みとはしていません。また、設定が認識されないと確定したわけでもありません。登録一覧を得られないため判定できない状態です。
