# 謎・伏線・解法・導線

制作者専用。解法は「プレイヤーに見える情報」から成立させる。ソース、JSのデータ、コメント、ファイル一覧、URL総当たり、開発者ツールを読む前提にはしない。

## 1. 序盤ルート（確定した方向と未実装の境界）

```text
外部note向けプロローグ草案
  ├─ memo夢記事(1) ─ 関連記事 ─ 使用感記事(2) ─ 明細画像の管理コード
  └─ TIME BACK(3〜12) ─ 運営会社名の検索など ─ Chronect(13〜)
                                               ├─ 事業・サービス ─ Business(33〜)
                                               │                    └─ 実証プログラム(41)
                                               │                         ├─ mapの公園名
                                               │                         └─ 明浜商店街振興会を検索
                                               │                              └─ 清掃写真(42)の像
                                               └─ 研究発表ニュース ─ [未実装のHub入口]
                                                                            └─ [管理コード照合]
                                                                                  └─ [売却中の本人の経路]
```

矢印の後半は制作方針の整理であり、現行サイトをクリックするだけで到達できる完成ルートではない。Chronect研究発表のどの記事がHub入口になるか、どの語句・リンクで入るかは未確定。

### 場所の手掛かり

1. 夢は「二つ重ねた銀色の輪」「公園の奥」「住宅間の細い道」「商店街」の組み合わせ。
2. 41番のアクセス図には明浜みどり公園・明浜商店街・本社と事業センターが載る。公園があるだけでは夢の場所の確定には足りない。
3. 本文の地域連携から「明浜商店街振興会」をBusinessで検索すると42番へ。
4. 清掃写真の背景に夢と対応する二重リング像がある。普通の清掃記事として成立する写真にする。
5. これで公園の一致を推理できる。ただし細道の全経路・施設到達・売却中の本人の移動は、写真だけでは証明できない。後続の履歴が必要。

「Chronectが公園を所有する」は確定していない。場所の一致と、Chronectへの近接・地域協力・秘密施設の存在を段階的に区別する。

### 明細の手掛かり

- 2番の記事で投稿者自身の売却を示す。画像を拡大して見られる。
- 実画像は `images/memo-timeback-receipt.png`。管理コードは **TB-260917-4826**、2026-09-17 13:00〜17:00、4時間、2,560円。
- 隣に処理番号P-0917-0318など普通の明細項目が並び、コードを露骨に強調しない。ぼかして読めなくしてはいけない。
- これは会員IDではなく管理コード。どの照会画面で何が出るかは未実装。
- 今後の履歴は同日・同時間帯・同一セッションと照合できる必要がある。【設計要件】であって、すでに存在するログではない。

### 最初の答え

【確定した制作判断】夢の景色は他人から渡った記憶ではなく、まつだ本人が売却中に訪れた場所。プレイヤーに最初から「記憶の移転では？」と文章で指示しない。

【未確定】夢として残る機序、どの程度の記憶抑制の不完全性か、本人がどの頻度で同じ道を通ったか。通常記憶が原則残らないという表向きの説明と、適切な段階で整合させる。

## 3. 検索によるルート制御

- 現在の3検索は互いに別の完全一致ホワイトリスト。検索語と該当先は [全登録一覧](09-search-and-links.md)。
- 本文の語句、出典、通常の資料名などから検索させる。検索用語を「」で囲って露骨に目立たせない。
- 不穏な演出で正解語を教えるのではなく、疑問を持った人が普通の情報を調べてつながる設計。
- Hub C/B/A階層と特殊検索は原案。現在のサイト内検索に実装済みと誤解しない。
- 原案の「1234,実験資料」は説明例であり、承認済み暗証語ではない。
- 「社員番号を検索で隠しページへ」は後の構想。今回も実装せず、将来の承認が必要。
- 2語検索、惜しい入力へのフィードバック、分岐合流、まとめの答え合わせは制作ガイドの方法論。全部が確定仕様ではない。

## 4. プレイテストで確認すべきこと

【整理案】正解語の見落とし、購入者は売却しないという思い込み、像だけで施設所有を誤認、全ニュースを順に読む作業化、コード判読のスマホ負担、早期の真相予測を観察する。

途中の答えは「この人は自分で訪れていた」まで。次の「なぜ？」を残しつつ、それまでの推理が前進したと実感できる証拠を配置する。
