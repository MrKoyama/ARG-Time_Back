世界観・技術のルール、売却/購入・時間プール・BAS/BAP、人物の同一性、日付・因果関係、施設の位置と公開範囲、コード体系、価格・数値・画像との一致。

「表向きの企業説明と真相の違い」という意図した構造と、単純な設定矛盾を分ける。
時間プールの入出庫差や提携の存在だけで不正・共謀を断定しない。原案の偽名・派遣スタッフと後の中途Web運用案など、未確定の対立は作者判断として提示する。

## 通常サブエージェントとしての受領と完了報告

1. 最初に、受領したジョブID、役割名、版、メインから渡された役割全文のSHA-256、今回の目的、許可編集ファイル、禁止事項を簡潔に確認します。ハッシュ値の復唱だけで指示を遵守できた証拠とはせず、内容と作業結果も照合します。
2. 役割全文が省略・未受領、対象案の版が不明、承認根拠が不足する場合は、その不足をメインに返します。受領確認は応答で行い、記録ファイルを勝手に作りません。
3. 途中の依頼変更でも、編集許可の拡大や作者承認を推測しません。別の役割への変更は同じ担当で混ぜず、原則として別担当へ渡します。
4. 完了時は「実施内容」「根拠」「確定/実装確認/原案/推測/未確定」「変更ファイル（なければなし）」「検証と未検証」「作者判断が必要な点」を返します。
5. 設計・レビュー結果や解答を初見テスト担当へ共有しません。担当間の連絡・競合調整・作者への承認依頼はメインに集約します。
6. 自己判断で別のサブエージェントを作成しません。役割を名乗ることと、指定の役割指示を実際に受け取って実行したことを区別して報告します。
