## No.98の日時表示

後半の「後日の連絡」に続けて、スレッド共通の「基準日時：YYYY/MM/DD HH:mm」を日本時間で表示する。No.84で第4返信を受信して進行が3から4になったとき、端末の受信時刻をミリ秒のUNIX時刻で一度保存する。表示は連絡1（事後報告）から連絡2（上司の返信）の順。各通の送信時刻や時刻差は設定していない。日時のない旧保存・不正値・No.1の掲載時刻（2026年9月28日21:14、日本時間）より前の値は「後日の連絡」の相対表示を使う。

後半は従来どおり進行4・5・6で表示し、削除や結末到達は条件に含めない。再読み込み・再訪では保存値を再利用し、会話リセット・分岐点復帰・完全リセットでは日時も消える。 [実装・保存仕様](07-development-and-design.md)

進行値と日時の保存は分けている。日時の保存に失敗しても受信済みの段階は保ち、日時欄だけ相対表示に戻る。別タブに残った前の会話の第4返信タイマーは会話開始時刻を確認して無効にする。完全リセットには既存の世代確認を使う。更新前から開きっぱなしのページは旧版の処理を使うことがあり、新しい日時キーが残る場合でも、初期化された段階では非表示となり、新版で次の会話を開始すると消去する。

## No.84 最初のクリックが反応しない報告の再調査

確認画面を一度も開いていないページから追跡した。HTTP・file:///の両方で、完全削除後の進行 `5` と結末到達の進行 `6` にすると、マウスを乗せた際にリセットボタンが赤くなり、クリックしても確認画面が開かなかった。同じボタンで `pointerdown` は観測できたが、HTMLの `disabled` によりブラウザは `click` を発火しなかった。ボタンにはクリックリスナーが登録され、確認画面のDOMもあった。ハンドラーの早期終了や例外で止まる形ではなく、クリックがハンドラーに届く前に無効化されていた。前回の閉じかけのオーバーレイがクリックを受け取る現象とは別に再現した。

削除前の第1〜第4返信後は、実ポインターの `click` が届き、確認画面に `is-open` と `aria-hidden="false"` が反映され、表示と初期フォーカスも正常だった。新規プレイ、日時キーがない旧保存、現行保存、No.84直接、No.82、アーカイブ、相沢から高瀬への切り替えを隔離Chromeで比較し、復元や切り替えの後もリスナーは1件だった。完了済みの報告書を完全削除したかどうかは会話進行の `5`・`6` で判定する。第4返信の日時キーはこの判定に使わない。直前の改修前後でNo.84のJavaScriptと参照バージョンは同一。現行のHTMLとスクリプトを組み合わせた隔離プロファイルでも現象が出た。作者のブラウザに配信されたHTML・キャッシュの組み合わせは未確認。

赤いホバー・フォーカス表示を有効なボタンに限定し、無効時はグレーと「報告書は完全削除済み」を表示する。完全削除後の操作制限、リセット処理、会話・報告書・他の進行の保存仕様は既存どおり。 [No.84の表示](../public/takase-mail.html)・[回帰テスト](../scripts/check-author-review-one.cjs)

修正後も同じ条件で、初回クリック、キャンセル、再表示、確定後の再開を確認した。1440pxのマウスと390・320px相当のタッチで確認し、完全削除済みの表示も画面内に収まった。完成報告書、相沢の会話、連絡先、訪問・エンディング履歴が保持されることを保存値で照合した。日時付きの第4返信後にリセットすると日時キーが消え、No.98後半が隠れた。再度第4返信を受けると新しい日時で表示された。検証中のJavaScript例外はなかった。

キャッシュ混在を想定し、C08より前の `takase-mail.js` と `investigation-report.js` を修正後のHTMLで読み込むローカル試験も実施した。旧保存の進行 `4` は初回クリックで開き、進行 `6` は無効の理由を表示した。これは配信を模擬した試験で、作者のブラウザのキャッシュには触れていない。

## C08 No.98後半の表示を再調査

作者は会話リセットを確認し、B03・B04を最終承認した。C08は後半の表示を再確認中。前半の固定日時は未判断。

現行HTMLには「旧社用メールへの対応について」の報告と上司の叱責がある。隔離Chromeで、会話開始前と第1〜第3返信後は前半のみ、第4返信後・完全削除後・ENDING 1到達後は前後半を確認した。ENDING 1から分岐点へ戻るとメール進行値と受信日時が消去され、No.98のアーカイブ再訪・再読み込みでは前半のみになった。高瀬宛ての会話を進め直して第4返信を受けると、後半と新しい日時が表示された。個別の会話リセット後も同じ結果だった。開いたままの別タブにも各状態が反映された。

通常の再プレイで第4返信を受け直して後半が出ない現象は再現しなかった。保存の表記を `4.0` にした検証では、No.84は第4返信までの8通を復元し、No.98は後半を隠した。No.84は数値に変換して判定し、No.98は文字列 `4`・`5`・`6` を比較していた。No.98も同じ数値の段階で照合するよう修正し、No.98から読み込むスクリプトの参照版を更新した。通常の保存処理は `4` を書くため、検証用の表記違いが作者環境の原因かは未確認。以前のスクリプトにも同じ文字列比較がある。本文、日時を記録する処理、会話・結末の到達条件は既存どおり。 [No.98の表示判定](../public/chapter-seven-reference.js)・[旧保存の回帰テスト](../scripts/check-ending-three.cjs)

修正後に同じ操作を再実行し、1440・768・390・320px幅で表示を確認した。隔離ChromeではJavaScript例外は発生しなかった。ENDING 1〜4の結合テストとアーカイブの回帰テストも通過した。作者の保存データでの表示は未確認。
